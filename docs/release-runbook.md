# TSRP preview, monitoring, and rollback runbook

This is a procedure for a future, explicitly authorized release. It does not mean TSRP currently has production monitoring, alerts, staged rollout, or rollback configured. No production deployment or configuration was changed by this task; repository edits remain local and uncommitted.

   - The current candidate has only process-local provider/task caps; there is no distributed ingress limit. ### Public API request limits

The code's bounded worker pool is process-local and is not a public request-rate limiter. Before public use, configure and verify a shared edge limit for provider-backed routes such as `/api/analyze`, `/api/search`, `/api/movers`, and `/api/top_stocks`. First observe legitimate traffic with a non-blocking/log rule, then select a threshold and 429 response that will control provider cost without blocking normal research. Current [Vercel WAF rate-limiting documentation](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting) (checked 2026-10-12) says fixed-window rate limiting is available on all plans, but counters are per region, so traffic across regions can exceed the configured threshold in any one region. Hobby includes one rate-limit rule per project, up to three total custom firewall rules, IP/JA4 keys, fixed windows from 10 seconds to 10 minutes, and 1,000,000 allowed requests. Pro allows up to 40 rate-limit rules and prices allowed requests usage-based, currently listed at $0.50 per million; check the account's live pricing/usage before enabling a rule. Do not assume a rate-limit rule is cost-free beyond the applicable allowance.

Configure WAF rate limits in the project's Firewall, not through `vercel.json` (whose documented WAF `mitigate` actions are challenge and deny). Publishing a Firewall rule takes effect on the production deployment immediately and does not require a code deployment. The dashboard may require review/acceptance of rate-limit pricing on first use. Do not configure, accept a billing prompt, or publish such a rule without explicit authorization. No limit is currently configured or published for TSRP.

## Monitor after an authorized promotion

- Record the deployment URL/ID, commit, promotion time, and the known-good rollback target.
- In the Vercel project’s deployment and function logs, inspect function startup/import failures, 5xx and timeout responses, duration, and the result of smoke checks. Vercel documents dashboard runtime logs across plans, but retention varies; do not assume alerts or log drains are enabled.
- The Python JSON API handlers emit one privacy-limited `api_request` record per response: generated request ID, allow-listed route, method, status, duration, outcome, safe error code, and exception class when applicable. JSON responses include the matching `X-Request-ID`, which is shown as a reference when the UI reports an API failure; the local development adapter exposes it only to its localhost origin allowlist. App logs do not include query strings, request bodies, IP addresses, or raw exception messages. Hosting access logs may still contain request metadata; do not paste them into public tickets.
- Check that ticker, company, reporting currency, timestamps, and analysis remain internally consistent. Review N/A, stale, and provider-unavailable states; a failure must not become a plausible-looking numeric result.
- No numeric latency/error-rate alert thresholds have been established for TSRP. Establish service baselines and alert thresholds before depending on automated monitoring. Until then, an absence of visible errors is not proof of health.

## Stop conditions

Stop the rollout and do not promote further if any of these occur:

- The page or any research section fails to load, navigation loses the selected company, or an older response overwrites a newer ticker.
- A Python function is missing, imports fail, required environment configuration is absent, or requests repeatedly return 5xx/504/timeouts during the controlled smoke checks.
- A source, reporting period, unit, currency, stale-data warning, or unavailable state is wrong or missing; a score/valuation is shown without its required evidence; or scenario facts do not reconcile with the displayed analysis.
- Logs or responses expose request bodies, personal text, credentials, provider payloads, or stack traces.
- Provider rights, legal approval, or a required security control is unresolved.

For a limited canary, abort or roll back the release candidate using the project’s configured controls. For a full production incident, use Vercel Instant Rollback only after confirming the target deployment and affected domains. Vercel eligibility depends on plan and deployment history; Hobby permits the immediately previous production deployment, while Pro/Enterprise can offer other eligible production deployments. A rollback restores a prior build, not changed environment-variable values or upstream provider behavior. After rollback, verify the domain and core analysis routes, inspect fresh logs, and follow Vercel’s documented procedure to restore normal deployment promotion when the incident is resolved.

## After recovery

Keep the failed deployment and logs available for investigation; do not delete the only known-good build. Record the trigger, affected deployment, user-visible impact, rollback target, and verified recovery. Fix forward on a branch, rerun the checks, and repeat Preview verification. Production changes require separate explicit authorization.

## Market-data provider rights: alternatives reviewed (2026-10-11)

Do not assume another API key or paid data plan resolves the current Yahoo rights gate. Official provider materials reviewed:

- [Twelve Data commercial vs personal use](https://support.twelvedata.com/en/articles/5332349-commercial-and-personal-usage) says individual plans are for personal/internal use and do not permit redistribution or commercial display; external distribution requires a separate agreement/add-on. Its [US equities licensing guidance](https://support.twelvedata.com/en/articles/9935903-us-equities-market-data) likewise says external distribution requires redistribution rights. Business pricing is substantial (the [published business pricing](https://twelvedata.com/pricing-business) currently shows Venture at $499/month billed annually), and market-specific conditions still apply.
- [Finnhub pricing for startups/enterprise](https://api.finnhub.io/pricing-startups-and-enterprise) lists commercial use with redistribution rights under its Enterprise offering, with flexible contact-sales pricing. The ordinary API-plan pages label listed plans “Personal Use”; this is not evidence that a public TSRP deployment is covered.
- [Financial Modeling Prep Terms](https://site.financialmodelingprep.com/terms-of-service) prohibit displaying its data through multi-user websites/apps without a specific agreement, even when the app is free. Its [pricing page](https://site.financialmodelingprep.com/pricing-plans?planType=commercial) states that data display/redistribution requires a specific Data Display and Licensing Agreement.

These are screening results, not legal advice or a definitive determination of TSRP's classification. No provider was contacted, account created, API key added, or plan purchased. Before replacing Yahoo, the owner must choose an affordable provider and get written confirmation covering the actual audiences, datasets, geography, display and exports, derived research outputs, caching, and intended educational/public use; obtain qualified review; then implement and test only against that contract. If no suitable rights are available, keep public market-data display disabled or keep the app private until resolved—do not relabel the source or assume derived outputs are automatically exempt.

# TSRP — Saleh Research Project

**Current hosted URL:** [thesrp.vercel.app](https://thesrp.vercel.app/)

> **Deployment note:** local changes in this checkout do not alter the hosted URL until they are pushed and deployed. Verify the deployed revision and test the live site before sharing it in an application.

TSRP is an independent, evidence-led equity research application for listed company stocks. The UI is Next.js App Router with strict TypeScript; the Python engine remains the single source of truth for scores, assumptions, and valuation calculations. Vercel routes the frontend and Python API as two services in one deployment.

The five primary research sections, in order, are **TSRP Score**, **Expectations vs Reality**, **Valuation**, **Catalysts & Risks**, and **What Changed?**. The score view is the home view. Ticker and section are encoded in the URL so links, refresh, and browser history retain the selected research view.

## Deploy to Vercel

The Vercel project must have the Services framework enabled for this two-runtime repository. In Project Settings → Build and Deployment, set the framework to **Services**; a `services` block in `vercel.json` alone does not enable Services mode. `vercel.json` defines a Next.js frontend in `frontend/` and a Python API service in `backend/`. TSRP is an open educational research project: anyone with the site link can use it without creating an account or signing in. The former sign-in page returns to research and `/api/auth/*` is disabled. The browser obtains a short-lived signed API token from the same site; this protects the internal frontend-to-API request flow, not access to the public app. Set `APP_ORIGIN` to the exact HTTPS origin for each deployed environment. Set `TSRP_API_TOKEN_SECRET` to a strong random value in both frontend and Python runtimes, and set a different `TSRP_SCENARIO_SIGNING_SECRET` in the Python runtime. Never reuse these secrets across environments. Rotating the API token secret invalidates older signed snapshots. Python 3.12 and direct dependencies are declared in `backend/pyproject.toml`; `backend/uv.lock` is the canonical, hash-bearing transitive lock used by Vercel, CI, and Dependabot. Set `SEC_USER_AGENT` only if you want SEC requests; use a real monitored contact identity. Yahoo Finance requires no API key, but the integration is disabled by default; do not enable `TSRP_YAHOO_FINANCE_ENABLED` until its data-use rights are cleared.

The Python API is implemented under `backend/api/`. A small ASGI entrypoint dispatches to the six existing `BaseHTTPRequestHandler` routes, keeping their validation and response logic unchanged. The backend entrypoint has a **60-second maximum duration** configured in `vercel.json`; a linked Preview must confirm Vercel applies that service-scoped setting. Vercel announced general availability of its Python runtime on October 15, 2026; Vercel Services remain Beta, the project must have its Framework set to **Services**, and actual access/routing/runtime behavior still needs a Preview check. See [Vercel Services](https://vercel.com/kb/guide/vercel-services) and the [Python runtime GA announcement](https://vercel.com/changelog/python-on-vercel-is-now-generally-available).

## Run checks locally

Use Node.js 22, pnpm 11, and Python 3.12. Install frontend and backend dependencies from the repository root:

```bash
(cd frontend && pnpm install --frozen-lockfile)
python3 -m pip install uv==0.12.19
(cd backend && uv sync --locked --no-install-project)
```

To run locally, no identity-provider or account setup is required. Use the same `TSRP_API_TOKEN_SECRET` in the frontend and Python processes. Start the loopback-only Python API adapter from the repository root:

```bash
TSRP_API_TOKEN_SECRET='<the same local secret>' backend/.venv/bin/python frontend/tests/asgi-http-server.py 8000
```

Then start Next.js from `frontend/`:

```bash
pnpm dev
```

The development server proxies `/api/*` to `http://127.0.0.1:8000` through its own origin, so browser requests do not need cross-origin permissions. `TSRP_DEV_API_ORIGIN` can select another `127.0.0.1` port for local testing; it is ignored outside development. The Python adapter is a local test harness, not a production server or a substitute for verifying Vercel routing. Company analysis can contact the configured external data providers.

Run frontend checks from `frontend/` with `pnpm lint`, `pnpm typecheck`, `pnpm test:node`, and `pnpm build`. `pnpm test` runs frontend Node tests plus the complete Python test tree, including root-level financial-engine tests and `tests/`; `pnpm test:python` uses the same full-tree discovery. The Python suite can also be run from the repository root with `PYTHONPATH=backend backend/.venv/bin/python -m unittest -q`. To change Python dependencies, edit `backend/pyproject.toml`, run `uv lock` from `backend/`, then run `uv sync --locked --no-install-project`; commit the manifest and lock together. The production-mode integration smoke is `TSRP_PYTHON=../backend/.venv/bin/python pnpm test:production-smoke` from `frontend/`; it starts the built Next.js app and the real ASGI entrypoint behind a temporary same-origin proxy on loopback, verifies that the page and API-token route work without a cookie, and completes a successful analysis using the deterministic synthetic `MockEquity` fixture. The test adapter mocks Yahoo and disables SEC, so no public market providers are contacted. This verifies the server boundary, not hosted Vercel routing.

## Architecture

- `frontend/app/`, `frontend/components/`, and `frontend/lib/`: App Router shell, interactive research views, navigation, charts, exports, types, and formatting.
- `backend/engine.py`: deterministic score, sector-model math, and reverse-DCF implementation; remains the calculation authority.
- `backend/financial_data.py`: period-alignment helpers for reported revenue and cash-flow observations.
- `backend/methodology.py`: sector calibrations reproduced from the prior research baseline. Parity fixtures and tests lock representative behavior.
- `backend/research_service.py`: server-only Yahoo/SEC adapters, currency conversion, provenance, validation, and analysis orchestration.
- `backend/api/`: server-side analyze, search, scenario, movers, and snapshot-comparison endpoints. Provider errors stay short and safe.
- `tests/fixtures/score-parity.json`: fixed baseline rates, sub-scores, weights, and DCF values for deterministic regression tests.

## Data sources, freshness, and limitations

- **Yahoo Finance through `yfinance`:** name search, listed-equity identity, quotes, daily price history, analyst revenue estimates, and supplemental financial statements. Its shared transport is disabled by default; set `TSRP_YAHOO_FINANCE_ENABLED=true` only after written authorization covers the actual access method, datasets, display/redistribution, audience, and intended use. This technical flag is not permission. Provider field coverage, delay, definitions, revisions, request limits, and permitted use are outside TSRP’s control. Yahoo Finance Help says information displayed or provided by Yahoo Finance must not be redistributed ([official help](https://help.yahoo.com/kb/SLN2310.html)); Yahoo’s [General Terms of Service](https://legal.yahoo.com/us/en/yahoo/terms/otos/index.html) also address automated collection and express prior permission, with region-specific provisions. TSRP uses the unofficial `yfinance` adapter, not Yahoo’s separately documented APIs; Yahoo API terms are therefore not evidence that this transport is authorized. These published materials are a material rights signal, not a legal conclusion about applicable terms, data-provider rights, or any separate permission that may exist. Obtain written authorization or replace the feed with a licensed provider before launch, with qualified review. TSRP does not claim real-time prices.
- **Top ticker:** when Yahoo access is explicitly enabled, separate server requests query Yahoo Finance day-gainer/day-loser and most-active US equity screeners, so failure of one list does not suppress the other. “Top movers” combines up to seven valid gainers/losers ranked by absolute daily percentage movement; “Top stocks” is a separate list of up to seven most-active equities, kept in Yahoo's volume ranking. If that screener is unavailable, the ticker labels a fallback “Popular stocks” and computes actual daily changes from Yahoo bars for AAPL, MSFT, NVDA, AMZN, GOOGL, META, and TSLA; those are not described as volume leaders. Changes use a positive previous close; pre/post-market quotes are used only when Yahoo supplies their own fresh timestamps. Partial source failures remain visibly unavailable instead of being filled with guesses. This unofficial `yfinance` screener access and any public display/redistribution rights have not been cleared—review current provider terms before release.
- **SEC EDGAR:** company ticker/CIK mapping and company facts when a listing is mapped and `SEC_USER_AGENT` contains a client/organization name plus exactly one monitored contact email. The app validates format, not whether the identity is truthful or monitored. SEC coverage is not universal for foreign listings. Missing identity, throttling, timeout, mapping, parse, or provider errors remain visible as unavailable states.
- **Foreign exchange:** Known quote subunits (GBp/GBX, ZAc, and ILA) use an exact fixed scale to their major currency; this is not represented as a market FX quote. When Yahoo access is explicitly enabled and the reporting currency differs, TSRP normalizes the quote subunit first and requests Yahoo Finance daily FX closes. A rate must be nonzero, fresh, and aligned with the market quote timestamp; cross-rate legs must also be comparable. The API discloses each unit-scale/FX step, pair(s), rate, and timestamp. Missing or misaligned FX makes dependent values unavailable; values are never relabeled in another currency.
- **Caching:** API responses default to `no-store`. Authenticated company analysis, movers, and top-stocks GET responses explicitly use `private, no-store`; search, scenarios, and snapshot comparisons are also not cached. The browser API client uses `cache: "no-store"`. TSRP does not configure shared edge caching for research responses. The Python service coalesces identical work only while requests overlap in one process; it does not retain completed responses as a cache or durable user state.
- **Financial periods:** free cash flow is calculated as operating cash flow less capital spending only when the relevant inputs match on reporting period and currency. Annual history is not described as TTM. Consensus, reported results, and model-implied growth use distinct labels and horizons.
- **Valuation:** TSRP's illustrative reverse-DCF sensitivity uses a ten-year growth fade and period-aligned reported inputs; it is not part of score-v8 and is not presented as a conventional DCF. Enterprise value is calculated from current market capitalization plus same-date total debt less cash; when Yahoo Finance lacks a total-debt row, TSRP sums only same-date current and long-term reported debt, and does not infer total debt from long-term debt alone. Other claims may be omitted. Market capitalization follows the listing quote currency and is converted to statement currency only with valid FX. Discount-rate and sector calibrations are static illustrative TSRP assumptions, not independently verified current market inputs. Valuation and scenarios are unavailable outside calibrated sectors. The solve is not a target price or fair-value conclusion; exact, outside-range, and unavailable states are explicit. User scenario values are separate from baseline analysis.
- **TSRP Score:** score-v8 combines business quality (53.8%) and financial strength (46.2%). The illustrative model-required growth sensitivity is excluded from the score because its cash-flow basis and discount assumptions are not independently validated; it remains separately disclosed in Valuation. Historical revenue growth contributes within Business Quality. Analyst revenue estimates are separate context, not a ten-year growth input, and are labelled by their supplied fiscal horizon. Historical CAGR and market-implied growth are directional, not matched-period expectations. Missing and undefined observations are excluded rather than assigned substitute scores; remaining weights are rebalanced. Each subscore requires at least 50% of its own factor weight; final score requires at least 70% evidence coverage and 70% of score weight available. See [`docs/research-methodology.md`](docs/research-methodology.md).
- No AI analysis, news provider, TSRP-managed account database, tracker, or server-side saved-research database is included. Anyone can use the app; it is not access-controlled. Next.js anonymous framework telemetry is disabled by the project scripts. No server-side persistent storage provider is configured.

## Privacy, security, and retention

When `TSRP_YAHOO_FINANCE_ENABLED=true`, ticker symbols, company-name search strings, and requests for the top ticker's gainers, losers, most-active-stock screeners, and fixed popular-stock quote fallback (AAPL, MSFT, NVDA, AMZN, GOOGL, META, TSLA) are sent from the server to Yahoo Finance; the transport is disabled by default. Company-search text is sent by the browser to TSRP in a JSON request body rather than a URL query; application logs omit request bodies and suppress yfinance diagnostics that could contain the ticker or search text. Search responses are marked `no-store`. The screener request does not include the user's search text or personal information. When enabled, SEC requests send the configured monitored `User-Agent` and a public company identifier to SEC endpoints. Assumptions are sent to TSRP’s own scenario API and are not sent to Yahoo or SEC. When comparing saved research, the browser sends only the required comparison fields from the current and selected saved analysis to TSRP’s snapshot-comparison API; TSRP does not persist those snapshots server-side. Providers and hosting infrastructure may observe request contents or metadata and apply their own logging and retention practices.

The app requires no sign-in and has no user-account database. Anyone who can access the URL can use it; do not treat the app as private or submit personal or confidential information. A short-lived signed API token is requested from the same site for each browser-to-API workflow, expires after 60 seconds, and is not stored in browser storage. This token is not an access gate. The app does not add analytics. When browser session storage is available, unsubmitted scenario assumptions are kept per ticker in the current tab so they survive refresh; they are cleared when the tab session ends or site data is cleared, and are not sent to TSRP until the user calculates a scenario. If the browser blocks session storage, the draft may not survive refresh. If a user explicitly saves an analysis, up to eight snapshots per ticker are held in that browser’s `localStorage`; snapshots are not synchronized or backed up and may be removed through **What Changed?** or by clearing browser site data. They contain public-company analysis figures, source/provenance fields, methodology version, and any user-entered scenario assumptions present in the analyzed result. This browser storage is not encrypted by TSRP and is shared within a browser profile.

Ticker inputs, query parameters, and scenario fields are validated server-side. Responses avoid provider payload dumps and exception details. Provider work is bounded to 12 workers and 24 outstanding tasks per warm Python process, with bounded route waits. This does not cap traffic across serverless instances or replace a distributed rate limiter. No distributed request-abuse control is configured in this repository.
